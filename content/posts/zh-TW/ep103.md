## 為什麼又回來用 Claude？

差不多半年沒聊 Claude 了，最近我又回來天天用它。原因很單純，Opus 5.5 太香了。結果 11 月 9 號 Fable 5.2 一上線，一代版本一代神，Opus 突然就有點阿巴阿巴。

你可能也是這樣用的：訂了 Claude，每天開一個對話，打字，等它回。它在跑的時候，你就在旁邊滑手機。額度用完，再等五個小時。

這篇整理 15 個我最近常用的小技巧，把這些等待的時間拿回來。先裝工具，再講怎麼讓它一個人帶一隊、怎麼顧好額度、怎麼把工作交給它接手，再看它怎麼找別的工具一起做，最後是我覺得人跟 AI 合作最順的用法。

先講一下範圍。下面講的都是 Claude 的桌面版 App，裡面 Code 那個分頁。終端機版大部分也有，兩邊不一樣的地方我會講。每一招的指令跟選單位置，我整理在[文末的清單](#指令與選單位置清單)，內文主要講它在解什麼問題。

## 怎麼在 Claude 裝 pstack？

### 第 1 招：裝 pstack

第一個，裝 pstack。它是 Cursor 放在 GitHub 上的一包技能，裝好之後 Claude 會多一排斜線指令，我拿它來學新東西、看懂別人寫的程式。常看這個頻道的人應該很熟了，白話課常常用它。外掛的入口有兩個。桌面版 App 是輸入框旁邊的加號，選加入外掛。終端機版就打斜線 plugin，會跳出外掛的畫面。

順序是先加 marketplace，再裝外掛。marketplace 你就想成一個外掛商店的網址。官方的商店一開始就有，pstack 放在另一家，所以要自己加。先把商店加進來，再裝 pstack：

![終端機裡先加 cursor/plugins 這個 marketplace，再安裝 pstack](/blog/ep103/install.jpg)

```
/plugin marketplace add cursor/plugins
/plugin install pstack@cursor-plugins
```

裝的時候它會問你範圍，有三種：你自己的每個專案都能用、這個專案的人一起用、只有你自己在這個專案用。選第一種最省事。懶得打指令的話，直接叫 Claude 幫你裝也可以，終端機有對應的指令，它自己會跑。

裝好之後，打斜線 pstack，它的技能就都列出來了。我最常用的是 teach。你打 pstack 冒號 teach，後面接你想學的詞，例如什麼是 CI。它會拿你手上的專案來舉例，講的都是你自己的程式碼。

同一包裡還有 why 跟 how，一個問為什麼這樣設計，一個問這段怎麼運作。第 97 集我還用過 technical-writing，拿它檢查那一集的稿子。這篇的結構也是用它調的。白話課的老規矩一樣：課不用買，拿你自己的訂閱、自己的專案來問就好。判斷很簡單：看到一個詞、一段程式看不懂，就丟給 teach。

## 怎麼讓 Claude 一個人帶一隊？

### 第 2 招：側邊對話

第二個，側邊對話。一個對話只有一條線。你中途插一個不相干的問題，它手上的工作就被打斷，那段問答還會留在對話裡佔位置。側邊對話就是另外拉一條線出去問。主任務跑到一半，我突然想問一個旁支的問題，就打斜線 btw，後面接問題，桌面版也可以按 Command 加分號。它會在旁邊另開一個小對話回答我，主線照跑。

側邊對話看得到主線到目前為止的全部內容，所以背景不用再講一次。它只回答，不會動手改東西，回答也不會放回主線。我做遊戲的時候，主線在改程式，我就在旁邊問它，參考的那款遊戲，技能是怎麼設計的。問完關掉，主線完全沒被打擾。我的準則：答案主線等一下用不到，就走側邊。主線要用，就直接在主線問。

### 第 3 招：背景工作

第三個，背景工作。一個對話一次只做一件事，查資料這種要讀很多東西的工作，還會把主線的對話佔滿。派分身出去，它在自己的對話裡做，只把結論帶回來。一件事可以拆開做的時候，我會叫它派幾個分身出去，直接跟它說派子代理在背景做就可以。像寫這篇的時候，一個分身去翻官方文件查證，另一個分身審稿，兩個都在背景跑，跑完自己回來報告。我這邊繼續跟主線講話。

更大的工作，可以整個對話丟到背景。終端機版打 claude 加上 bg 參數，後面接任務，它就自己在背景做。桌面版的側邊欄，每一個對話就是一列，哪個在跑、哪個在等我回話，一眼看得到。這些都跑在你的電腦上，電腦關機它們就停了。我的分法：要讀很多東西、結論一句話講得完的，派分身。要我一路盯著改的，留在主線。

### 第 4 招：工作中插話

第四個，工作中插話。它還在跑，我想到要補一句，直接打字送出去就好。桌面版 App 裡，它做完手上這一步，就會讀到我那句，接著照新的指示改。終端機版也一樣。終端機裡的斜線指令，大多要等它這一輪做完才跑。

為什麼是做完手上這一步才讀？AI 代理做事是一個迴圈：想一下、動手做一步、看結果，再想下一步，一直轉到做完。你中途送出去的話，要等它轉到哪裡才讀，有兩種設計。

一種做法叫 queue，排隊。你的話先放著，等它這一輪做完才讀。另一種叫 steering，轉向。它每做完一步就看一下你有沒有新指示，馬上改方向。現在 Claude 一般的訊息都走 steering，終端機裡的斜線指令大多走 queue。

![queue 是等這一輪做完才讀你的話，steering 是每做完一步就讀](/blog/ep103/queue-steer.jpg)

steering 還是同一條迴圈，它一樣一次只做一件事，只是讀你的時機變早了。現在這些都由包在模型外面的那層程式處理，這層我們叫 harness。它決定什麼時候把你的話遞進去，要同時做別的事，就交給前面講的側邊對話跟背景工作。你只管打字。所以想到就打，它停下來之前就會讀到。

![harness 包在模型外面，決定什麼時候把你的話遞進去](/blog/ep103/harness.jpg)

## Claude 的額度怎麼省？

### 第 5 招：自動壓縮

接下來是額度。第五個，自動壓縮。先講它在解什麼問題。你每送一句話，Claude 都要把整段對話從頭帶一次。對話越多，每一句話花的額度就越多，回得也越慢。所以對話多到一個程度，它會把前面的內容壓成摘要再繼續。

這個程度可以自己調。Opus 5.5 預設能裝一百萬個 token，token 你就想成字數，差不多到 97 萬才會壓。我打斜線 autocompact 400k，把它調成四十萬。範圍是十萬到一百萬，想回到預設就打 autocompact auto。

調短之後，每一輪送出去的東西變少，額度用得慢，回得也比較快，我日常用是夠了。代價是壓縮的時候細節會掉。所以重要的規則，我會叫它寫進專案的說明檔，壓縮之後它重讀一次就都回來了。你常常一個對話用一整天，就調短。每個對話都很短，放著預設就好。

### 第 6 招：對齊五小時的額度

第六個，對齊五小時的額度。官方說，五小時的額度從你送出第一則訊息開始算，五小時後整個更新。假設你九點開工，九點才送第一句，額度要到下午兩點才更新。下午做到一半卡住，就只能等。

所以我在桌面版排了一個排程，每天早上七點，叫最便宜的 Haiku 回一句 OK。這一輪就從七點算到十二點。我九點開工用到中午，吃個飯回來，下午是一整輪新的額度。這是我自己的用法，官方沒寫。下次更新的時間，在設定的 Usage 那一頁看得到。你今天就可以排一個，明天早上看更新時間有沒有往前。

![早上七點叫 Haiku 回一句 OK，第一輪從七點算到十二點，下午是一整輪新的額度](/blog/ep103/align-how.jpg)

順便講排程本身，一共三種。雲端排程跑在 Anthropic 的機器上，電腦關著也會跑。桌面排程要 App 開著、電腦醒著，錯過的會在你回來之後補跑一次。還有斜線 loop，在目前這個對話裡定時重複一件事，對話要開著，七天後自動過期。我每天早上叫 Haiku 的那個，用的是桌面排程。

![三種排程的比較表：跑在哪、電腦要不要開、錯過會不會補跑、多久過期](/blog/ep103/schedule.jpg)

### 第 7 招：重置券

第七個，重置券。開頭講到，Fable 一出來，Opus 就阿巴阿巴了，那 Fable 額度不夠用怎麼辦？沒關係，Claude 也學了 OpenAI Codex 團隊 Tibo 那套祖傳的額度重置。這次 Fable 上線，Max 跟 Ultra 的用戶，訂閱滿一年的拿到三張，不滿一年的一到兩張，用到明年 3 月 8 號。Pro 是一張，11 月 16 號已經到期。

一張重置券，會把你這週花在 Fable 上的額度退回來，五小時的額度也整個補滿。舉個例子，週額度用了八成，其中五成是 Fable 花的，按下去就回到三成。花在其他模型上的額度留在原地。

![按下重置券之後，週額度從八成回到三成，五小時額度補滿](/blog/ep103/reset-how.jpg)

週額度更新的日子照舊。OpenAI 那邊，照 Qualiteg 的整理，重置之後下一次更新的時間會跟著往後挪。Claude 這次出手這麼大方，看起來 Dario 搶到不少算力，這是我自己猜的。

什麼時候按最划算？我的算法是這樣。先估一下：按下去退回來的額度，在這一週剩下的幾天裡用得完，就按。用不完，按了也是白按。週額度剛更新的時候，沒什麼可以退。快要更新的前一天按，退回來的額度隔天就被更新蓋掉。所以通常落在一週的中間，實際還是看你那一週事情多不多。按下去就收不回來了。

要提醒一下，重置券要到網頁版或 App 的設定，Usage 那一頁按，Claude Code 裡面按不到。一張券只能按一次。

## 怎麼把工作交給 Claude 接手？

### 第 8 招：接力下指令

第八個，接力下指令。有些指令 Claude 會交給我來跑，例如要動到系統的安裝。它把指令寫好，旁邊有一個 Run 按鈕，我按下去，指令就在側邊的終端機跑。我不用複製貼上，也不會打錯字。

遇到要打密碼的 sudo，我自己點開那個終端機把密碼打完，密碼不用貼進對話。跑完的結果，它可以去讀終端機的畫面，接著做下一步。一個指令兩個人接力：它寫，我按，我打密碼，它看結果。分工的準則：要密碼、要我本人確認的，我來按。其他的讓它自己跑。

### 第 9 招：Remote Control

第九個，Remote Control，用手機接手電腦上正在跑的對話。工作在電腦上跑，人卻常常得離開電腦。它停在那裡等你按同意，你人在外面，整件事就卡住。終端機版在對話裡打斜線 remote-control 把它打開，桌面版可以在設定裡設成預設打開。我出門的時候，打開手機的 Claude App，或是瀏覽器開 claude.ai 的 code 頁面，就能接著操作電腦上同一個對話。它問我要不要允許某個動作，我在手機上按同意。想到要補的指示，手機上打字送過去。

程式一直在我的電腦上跑，檔案也都留在我的電腦，所以電腦要開著。拿我之前介紹過的 Grok Bot 跟 Codex 來比，它們可以控制整台電腦，Claude 這邊收得比較保守，遙控的是那一個對話。我日常用，這樣已經很方便了。

### 第 10 招：雲端環境

第十個，雲端環境。Remote Control 還是要電腦開著。有些工作只需要程式碼，用不到你電腦上的任何東西，那就整件事搬到別人的機器上做。桌面版開新對話的時候，環境選雲端，或是終端機打 claude 加上 cloud 參數，整件事就丟到雲端的機器上跑。筆電闔上也沒關係，它做完，我回來再看結果。雲端機器不另外收錢，用的是你方案裡的額度。

這三個怎麼選？放在一起看。背景工作跑在我的電腦上，我人也在電腦前，只是想同時做別的事。Remote Control 也跑在我的電腦上，差別是我人出門了，工作要用到本機的檔案、模擬器、已經登入的帳號。雲端環境跑在 Anthropic 的機器上，電腦可以關，適合只需要程式碼、改完開一個 PR 就結束的工作。

![背景工作、Remote Control、雲端環境的比較表](/blog/ep103/choose.jpg)

### 第 11 招：PR 追蹤修復

第十一個，PR 追蹤修復。程式寫完只是一半。PR 開出去之後，還要等自動測試、等別人審、修到能合併，這一段最花時間，也最用不到人盯，這段時間就交給它顧。電腦要先裝好 GitHub 的 gh 指令、登入。它開了 PR 之後，我在 PR 的狀態那邊把 Auto-fix 打開。自動測試掛了，它會自己醒來去修，修完推上去。別人在 PR 上留的審查意見，它也會處理。

留言的意思模糊的時候，它會先回來問我。遇到程式衝突，要叫它 rebase。旁邊還有一個選項叫 Merge when ready，檢查全過就自動合併，這個我會看情況開。平常我只要最後看一眼，決定要不要合併。

## Claude 怎麼找別的工具一起做？

接下來拿我最近在 PA Cafe 裡做的一款小遊戲來示範，叫 BARISTA BLAST。從咖啡機發射出去，一路撞街上的 AI 住民，看能飛多遠。街上有八位住民，每一位都有立繪、台詞、語音，還有每一區的背景音樂。這些素材，都是 Claude 指揮別的工具做出來的。

這款遊戲的起點是一句話。11 月 14 號早上，我貼了一款老遊戲 Nanaca Crash 的網址給 Claude，跟它說：搞一個這個，撞的是各個住民，距離改成 token，配一些有趣的梗。它先開了一張 issue 把規劃寫出來，我們來回改了三版，前面兩個半小時都在談規劃。中午我看過就開工，兩個小時內就有一局能玩。當天傍晚第一版合進主線，另外加了 3D 街景。

接下來幾天，我做的事就是邊玩邊丟意見。我說 token 的單位太小，最遠要能打到幾十 B。我說這遊戲是拿來引流的，有梗比平衡重要。立繪我覺得圓滾滾的二頭身比較搭，就整批再畫一輪。到 11 月 17 號，合併了六十幾個 PR。

![BARISTA BLAST 四天內合併 PR 的累積曲線：當天傍晚第一版合併，之後四天邊玩邊改](/blog/ep103/game-turns.jpg)

前面講的那幾招，這裡全用上了。最多的時候，同時有八個對話在跑。有一次我一分鐘內連開四個：音效、街上住民的表情、新手導覽、分享頁的選單。四個各自做，做完各自開 PR。

### 第 12 招：呼叫 Codex

第十二個，呼叫 Codex。Claude 自己不畫圖，角色立繪我交給 Codex 的生圖，用的是我的 ChatGPT 訂閱。Claude 寫好提示詞、附上參考圖，在終端機叫 codex exec 跑，一張圖跑一次。

附參考圖是為了讓同一個角色每一張都長得一樣。圖生出來之後，Claude 再選圖、去掉背景、放進遊戲。同一位住民有平常的衣服、進了神界的另一套衣服，還有兩個人的合體畫面，都是這樣一張一張跑出來的。

### 第 13 招：Colab 生素材

第十三個，Colab 生素材。第 99 集講過，Google AI Pro 訂閱裡附的 Colab 顯卡額度。背景音樂用開源的音樂模型 ACE-Step 生，角色大招的語音用 Qwen 的語音模型唸。Claude 用 Google 官方的 Colab 指令開一台有顯卡的機器，在上面跑完，再把檔案抓回來。

音樂每一首都生兩個版本，我聽完選一個接進遊戲。語音是每位住民先定一個聲線，再唸幾句大招台詞。整個過程我沒有開過 Colab 的網頁，都是 Claude 在終端機裡做完的。

你把它想成一個導演。Claude 負責寫提示詞、派工作、驗收，畫圖交給 Codex，要顯卡的交給 Colab。幾個訂閱裡本來就有的額度，就這樣被它串在一起用。我的準則：Claude 自己做不到的事，先看手上哪個訂閱做得到，再叫它去指揮。

## 人跟 Claude 怎麼合作最順？

### 第 14 招：引用回覆

最後一章講合作。第十四個，引用回覆。它回了一大段，我只想針對其中幾句講話，就把那幾句選起來引用，在下面寫我的意見。可以連續引用好幾段，一段一段回，最後一次送出。

它會照每一段分別處理。這篇的大綱就是這樣改出來的。它先給我一份大綱，我引用了七段，有的回一個字「可」，有的補一整段用法，一次送出去，它一次改完。換成一來一回地問，要來回七輪。一則回覆裡有兩個以上的點要回，就用引用。

### 第 15 招：Artifacts

第十五個，我覺得是人機協作最好用的一招，Artifacts。東西一多，要看圖、要聽聲音的時候，我就跟它說做成一頁 Artifact。Claude 可以直接做一個網頁，發布到一個網址給你看，預設只有你自己看得到。像這頁，BARISTA BLAST 的素材總覽。

前陣子很流行一個說法：AI 回你一大篇 Markdown，滿滿都是字，讀起來很吃力，直接給你一頁 HTML 好讀得多。有圖、有表格、可以點、可以聽。Artifacts 就是 Claude 對這件事的答案。

![左邊是一大篇 Markdown，右邊是同樣內容做成一頁 HTML](/blog/ep103/artifact-why.jpg)

這一頁把遊戲的素材分成十幾區，從 A 排到 R。圖片點一下可以放大，音樂跟語音按一下就能聽。每一張圖、每一段聲音都有代號，我要改哪一張，講代號就好，例如 A3、G10。

![BARISTA BLAST 素材總覽頁，分區 A 到 R，每張圖都有代號](/blog/ep103/artifact-layout.jpg)

還有一個很直接的做法，在頁面上留言。我看到哪張圖想改，就在那裡留言，按 Send to Claude，或是在留言裡標 @claude，它讀到就去改，改完同一個網址更新。

![在 Artifact 頁面的圖上留言，送給 Claude](/blog/ep103/artifact-comment.jpg)

這一頁是這樣來的。11 月 16 號晚上，我跟它說：開個 Artifacts，把主要的視覺排出來，我看看哪些要美化。五分鐘後第一版就出來了。我邊看邊留言，像是 G11 這張的月亮怎麼有兩圈，A2 的立繪邊緣缺了一角。到隔天早上，這一頁已經更新到第十三版。

要比較視覺的時候，我會叫它同一個畫面做好幾版，並排放在一頁給我選。每一次發布都是一個版本，改壞了可以回頭看之前的。很久以前，我自己替影片工作流做過一套預覽、標註、修改，現在這些都內建了。

舉個實際的例子，PA Cafe 的首頁。我跟它說，先出幾版視覺給我看看。它在同一頁放了三版：暖光櫥窗、黑板菜單、任務看板。我看完說想混搭，它再出第四版。接著我在頁面上留了四十幾則留言，最後從任務看板那一版改到定案，前後大概三個小時。

遊戲的台詞我也是這樣校對的。台詞加演出一共三百多項，我叫它做成一頁，每一項旁邊有可以跟要改兩個按鈕。我一項一項點過去，它讀我點的結果，把我同意的句子直接改進 PR。

做好的頁面可以分享。右上角的 Share，可以開給組織裡的人，也可以公開，把連結丟給對方就好。要拿去別的地方用，也可以匯出成一個 HTML 檔。

## 你最想先試哪一個？

![Claude 15 招總表：招名、解什麼問題、在哪開](/blog/ep103/recap.jpg)

## 指令與選單位置清單

這份清單是 2026 年 11 月 17 日的狀態，以 Claude 桌面版 App 的 Code 分頁為主。介面跟指令之後可能會改，對不上的時候以官方文件為準。

| 招 | 指令或位置 |
| --- | --- |
| 1 裝 pstack | 桌面版：輸入框旁的「＋」› Add plugins。終端機：`/plugin marketplace add cursor/plugins`，再 `/plugin install pstack@cursor-plugins`。用法：`/pstack:teach 什麼是 CI` |
| 2 側邊對話 | `/btw 你的問題`，桌面版也可以按 ⌘ ; |
| 3 背景工作 | 直接跟它說「派子代理在背景做」。整個對話丟背景：`claude --bg "任務"` |
| 4 工作中插話 | 它在跑的時候直接打字送出 |
| 5 自動壓縮 | `/autocompact 400k`，範圍 100k 到 1M；回預設用 `/autocompact auto` |
| 6 對齊五小時 | 桌面排程：每天 7:00、模型選 Haiku、內容「回 OK」。下次更新時間在 設定 › Usage |
| 7 重置券 | 網頁版或 App 的 設定 › Usage。Max、Ultra 的券到 2027 年 3 月 8 日；Pro 的那張 2026 年 11 月 16 日已到期 |
| 8 接力下指令 | 它寫好的指令旁邊有 Run 按鈕；要打密碼就點開側邊終端機 |
| 9 Remote Control | 終端機：`/remote-control`。手機開 Claude App，或瀏覽器開 claude.ai 的 code 頁面 |
| 10 雲端環境 | 桌面版開新對話時環境選 Cloud。終端機：`claude --cloud "任務"` |
| 11 PR 追蹤修復 | 先裝 GitHub 的 `gh` 並登入。在 PR 狀態那邊打開 Auto-fix；Merge when ready 看情況開 |
| 12 呼叫 Codex | 叫 Claude 在終端機跑 `codex exec`，用 `-i` 附參考圖 |
| 13 Colab 生素材 | 叫 Claude 用 Google 的 Colab 指令列工具開一台有顯卡的機器，細節見[第 99 集的文章](/blog/ep099) |
| 14 引用回覆 | 選取它回覆裡的幾句話 › 引用，可以連續引用好幾段再一次送出 |
| 15 Artifacts | 跟它說「做成一頁 Artifact」。頁面上留言後按 Send to Claude 或標 `@claude`；右上角 Share 可以分享或匯出 HTML |
