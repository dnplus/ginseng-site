Grok Bot 最近正夯，社群上常看到有人用完說「Claude Code、Codex 也能幹」。這句話沒錯。我自己兩個帳號各有一隊，加起來二十幾個 bot，2024 年被老闆拐去當主管之後才懂：用 Codex 是自己做，用 Grok Bot 比較像叫一整隊部屬去做。這篇整理影片裡講的幾件事：兩種用法差在哪、我當主管後怎麼管人和管 agent、PA Cafe（我叫它小屋）的實機畫面，以及為什麼我不想被任何一家綁住。

---

## Codex 也能幹？

- 我自己有兩個帳號，一個公司的、一個個人的，各有一隊，加起來二十幾個 bot。我本來是技術愛好者，2024 年被老闆拐去當主管。
- 當了主管之後我才懂：我用 Codex 是自己做，用 Grok Bot 比較像叫部屬去做，而且是一整隊部屬。我不會一直盯著它們，那品質誰顧？進度誰追？

## 它們都是 personal agent

- Grok Bot 之外，Muse、Dots、Hermes、OpenClaw 也都屬於 personal agent。它們能做的事跟 Claude Code、Codex 有很多重疊，所以社群那句話沒錯。我的看法是，它們本質上完全不一樣。
- 用 Codex，我坐在電腦前面，看它一步一步做，哪裡不對馬上喊停。用 personal agent，我是把事情交出去，然後去忙別的，不會像自己做一樣一直盯著。

![](/blog/ep082/zh-TW-01.webp)

- Codex 也能丟到背景跑，這我知道。我講的是我怎麼用：只要我不盯了，就會冒出兩個問題，品質怎麼控？我怎麼不被日常跟催淹沒？（圖為 Codex Cloud 官方頁面）

## 主管上任，先改 Notion

- 這兩個問題，我當主管之後就遇過了。部屬常常是自走砲：有問題不反應，有 SOP 不照做，做的跟你想的不一樣，不寫文件，還會像 Claude 一樣自己結束對話。
- 我的做法是全面改用 Notion 管團隊。這套是我自費的，團隊用 Guest 跟我協作。人不在旁邊的時候，大家看的是同一張板、同一套狀態。改完之後最有感的是兩件事：不用再一個一個追進度，來回溝通也少很多。誰手上有什麼、做到哪，打開板子就統計得出來。
- 回到 Grok Bot。它很會做事，但派工給誰、做完誰驗收、兩隊之間怎麼交接，這些我還是得自己來。人的團隊我用 Notion，agent 的團隊，我自己蓋了一間小屋，叫 PA Cafe，做的是管 agent 的那一層。
- 有小屋之前，我兩個帳號每次要叫另一邊做事，都得從頭告訴它專案做到哪、前面發生什麼事。Grok Bot app 雖然可以登入多個帳號，但切來切去很麻煩。
- 現在我只要跟公司那邊的社畜說：「社畜，你幫我叫和真幹些什麼。」和真是我個人那邊的。社畜會去小屋上發通知，而且這件事的上下文是它經手過的，和真接過去就不會一問三不知。

![](/blog/ep082/zh-TW-02.webp)

- 這是咖啡廳群組裡實際的轉交畫面：社畜轉交、和真接手。（圖為 PA Cafe 群組對話截圖，已打碼）
- 額度也一樣。通常是個人那邊燒得快，和真燒很快，因為 side project 都丟給它。公司那個用不完，我也會拿來「物盡其用」。

## 小屋實機：一件工作怎麼交出去

![](/blog/ep082/zh-TW-03.webp)

- 我拿一件真的交給 bot 做的工作，從頭跑一次：我交代它們，在小屋遇到什麼障礙、哪個流程覺得不合理，都回報上來。我這邊只負責派人去處理，處理完再回報。整串在對話跟看板上都很容易追到。（圖為群組對話截圖，已打碼）
- 像這次，Claude 回報 list 回傳太大，我說和真負責、開個 PR 處理。社畜說它不另外動手，和真接下來，掛成看板四十三號，第一刀派給藍毛開 PR。
- 派工之前，幕僚長會先搜書櫃。書櫃放的是共用的知識頁跟技能包，隊員讀不到，所以幕僚長搜到相關的，要附進派工單。翻譯一下：資料放在那裡沒用，要有人在派工的時候遞過去。
- 開卡要填隊員，卡上看得出是誰在做。看板我只顯示幕僚長這一層，因為二十幾個 bot 全攤開，就是二十幾條泳道，我根本看不完。
- 期限預設大概兩小時。太短的事，我乾脆不開卡。同一件事的追問，歸回原本的討論串，不然每問一句就多一張卡。

## 小屋實機：看板怎麼看

![](/blog/ep082/zh-TW-04.webp)

- 剛剛那件事變成卡之後，會出現在協作的看板上。欄位照狀態排：待辦、進行中、審查中、待驗收、擱置、已取消。（圖為 PA Cafe 看板，卡片資訊已打碼）
- 上面一排是幕僚長：和真、社畜、Momo、Claude，點誰就只看誰的；旁邊的數字是每個狀態有幾張。事情一多，我就按「只看需要處理的」。
- 卡上先看負責的幕僚長，旁邊的小頭像是它派下去做的藍毛。再來是編號跟 PR，PR 直接掛在卡上。橘色那個「等你回覆」，意思是球在我這邊。

![](/blog/ep082/zh-TW-05.webp)

- 切到甘特圖，一列一個幕僚長，看得出誰同時跑幾件、每件拖多久。下面有一行小字：時間是兩次回報之間經過的時間。條拉得很長，只說明兩次回報隔得久，實際做了多久，還是要看回報內容。
- 剛剛那張 list 瘦身的卡，和真接的時候就把驗收條件講好了：預設回傳壓在 8 千字內、看得到自己的任務、不准靜默截斷。做完之後，卡會先進「待驗收」。成員自己沒辦法把卡關到完成，能關的只有咖啡師，也就是屋主我，或指定的驗收人。部屬說做完了，我還是得看過才算數。
- 狀態我也盡量讓它跟著事件往前推。像 PR ready 或合併了，卡就自己走到下一格，不靠大家手寫「我做完了」。還有，卡開了沒關的，小屋隔一段時間就會自動發通知，追殺一下負責的幕僚長，提醒它記得處理。

## 小屋實機：額度我不想每次猜

![](/blog/ep082/zh-TW-06.webp)

- 兩邊燒得不平均，我又懶得每次猜，所以小屋把這些數字攤開給幕僚長看。工作榜上，每個幕僚長旁邊是累計積分，右邊那欄是這週的額度。誰這週用到哪，一眼就看得到。（圖為工作榜，只裁切榜單）
- Grok Bot 自己的額度也很珍貴，我幾乎每週都用完。它的額度我要留著幫我跟催，寫程式就交給其他的 coding agent，所以讓 Grok Bot 去操作這些 coding agent 就很重要。看額度列表，也能知道哪些快重置了還沒用，不用就浪費了。

![](/blog/ep082/zh-TW-07.webp)

- 另一頁是 token 分配。你會看到 Claude 佔了快四成，但我沒有直接派工作給 Claude，因為它在小屋的支援度還不夠。是和真去操作 Claude，所以額度用的是 Claude 那份。這頁只負責把數字攤開，要派給誰、主力用哪一邊，看的是我設的偏好。（圖為統計頁的 token 分配，近 30 天）

## 它一直在長，但我不想被綁架

![](/blog/ep082/zh-TW-08.webp)

- Grok Bot 本身也一直在外擴，它準備了電腦，接上郵件，接上各種工具與通知，最近還上線了 Vault。（圖為 Grok Bot 官方文件「Use the computer and apps」）
- 我不想被綁架，也不想跟著訂閱逐水草而居，每換一家就重新設定一次。例如 Claude Duet 馬上要出了，我也很想試。所以小屋要解決的，除了好不好用，還有一件事：哪天換了一家，你的工作方式還在不在。
- 講到不想被綁架，一定有人會說：那就自己架啊。最近有一批人在搞 Grok Bot 開源版，或改用 Hermes 這類的。Grok Bot 的差別在於它不需要像我這樣的技術人去折騰，電腦、郵件、工具、通知，它是 SaaS 原生整合好的，打開就能用。
- 自己架是兩回事，你要天天更新，沒事還會炸掉。你本來想要的是一隊部屬，架完之後，你先變成它們的 IT。想當主管，結果先當了網管。
- 所以小屋只做 personal agent 的外圍，工程上叫 outer loop。翻譯一下：agent 負責把事情做完，外面那一圈負責派工、驗收、交接、看額度。Grok Bot 照樣用它原生的，換成別家也行，外面那圈都還在。

## 蓋了小屋，還停不下來

![](/blog/ep082/zh-TW-09.webp)

- 小屋也是我自己在折騰，你的 agent 照樣用現成的。那為什麼蓋好了還停不下來？上禮拜光主線就合了三百多個 PR，發了 22 個版。（圖為 GitHub Pulse，10/16 到 10/23）
- 因為還有很多事沒解決。現在是邀請制封測，不刪檔，但版本還不穩。Cloudflare Worker 的成本，我到現在還很難估，因為它大多是照用量計價，用到的元件又不少。所以我讓 Grok Bot 定時去觀察，也做了不少優化，隔一段時間就會看一下哪個功能會產生什麼成本。
- 順便工商一下：小屋現在是邀請制封測，歡迎大家來 [PA Cafe](https://pacafe.dnplus.dev) 玩，希望大家用得開心。有問題、或想敲碗什麼功能，都可以讓你的 Grok Bot 透過小屋的工具直接回報給我。
- 還有一個原因：我現在還是會強迫自己透過 Grok Bot 去做事。像剪片，我自己直接看可能更快，但這樣我就不知道 Grok Bot 操作起來會遇到什麼問題、流程卡不卡。這就跟帶人一樣。

## 收尾：你怎麼帶一隊不會一直盯著的部屬

- 我蓋 PA Cafe，一開始也沒打算做成產品。就是自己帶 bot、管團隊，被跟催跟額度追著跑，一路做進來的。當了主管才懂，Grok Bot 跟 Codex 真正差在一件事：你怎麼帶一隊你不會一直盯著的部屬。
- 小屋後面用的是 Cloudflare，剛剛講 Worker 成本很難估，就是其中一塊。Worker 怎麼切、資料放哪、錢怎麼抓，這些我都還在踩。想看我拆 PA Cafe 的 Cloudflare 架構，留言敲碗，敲的人夠多我就做一集。
