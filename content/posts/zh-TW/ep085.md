最近有不少重磅的資安事件，像是 PHP 的漏洞，我工作上剛好也會接觸到這一塊。所以這集想聊：如果我自己做一個 SaaS，一個獨立製作的服務，資安應該做到什麼程度？這也是我自己還在想的問題，這篇整理我目前的看法，還有 PA Cafe 小屋（以下簡稱小屋）實際怎麼做、怎麼取捨。

## 部署之後，換資安擋路

上一集講小屋怎麼架上 Cloudflare。寫程式、CI、部署，現在都有辦法交給 AI 和 agent。這些都解掉之後，真正擋在面前的是資安：服務一上線，就有真的人在用，真的資料放在上面。

Zeabur 被駭的事件，官方初步報告說有 32 萬多個帳號受影響，外洩的是環境變數，也就是大家放 API key、資料庫密碼的地方。平台能做的是撤銷憑證、發指引；放在上面的金流、email、資料庫、AI API 金鑰，還是要用戶自己一個一個換。我看到新聞的第一個念頭是那些用戶好慘，還有那些工程師也很慘：應變有時效性，出事那幾天應該很多人天天加班。

![Zeabur 初步報告：外洩的是環境變數](/blog/ep085/zh-TW-01.webp)
*Zeabur 初步報告：外洩的是環境變數*

現在一個行銷、一個業務、一個 PM 都能靠 AI 做出東西，我自己也是靠 AI 一個人做出小屋。做得出來，跟顧得好，是兩件事。把服務丟上一鍵部署平台的 citizen developer，可能不知道自己的 API key 放在哪、資料庫有沒有對外開、平台出事時自己要做什麼。

攻擊的那一方現在也有 AI。Anthropic 九月的濫用報告說，攻擊者已經讓 AI 從助手變成指揮者；Fortune 報導其中一個案例，一次攻擊拿走大約 200 家客戶的資料，幾乎全由 AI agent 完成。

## 資安觀念：弱點與拖時間

我的前提是：所有系統都會被攻破，問題在於它為什麼要攻擊你。小屋上面最有價值的是大家的 token，所以小屋把 token 加密，這是營運方的責任。

以前很多系統都有漏洞，只是開採漏洞要成本。現在 AI 可以 24 小時無人值守地做這件事。Fortune 那篇的標題就是：AI 可能讓更多公司變得值得駭。

### PHP 這次的例子

10 月 21 日 PHP 官方發了修補版，美國 CISA 同一天發公告要大家馬上更新，因為其中的漏洞讓攻擊者不用登入就能執行程式碼。接著北部就是颱風假加連假，放了四天；漏洞已經公開，攻擊可不會跟著放假，那幾天應該很多人在家裡修。

![CISA 10/21 公告：PHP 漏洞需立即修補](/blog/ep085/zh-TW-04.webp)
*CISA 10/21 公告：PHP 漏洞需立即修補*

Cloudflare 這次也出手，又是賽博菩薩：漏洞公開前大約九小時就把防火牆規則推上去，免費方案也有，預設就擋。它擋的是經過 Cloudflare 的流量，原站本身的洞還在，所以 Cloudflare 自己也建議 PHP 還是要更新。

![Cloudflare Blog：WAF 規則在漏洞公開前上線，仍建議更新 PHP](/blog/ep085/zh-TW-05.webp)
*Cloudflare Blog：WAF 規則在漏洞公開前上線，仍建議更新 PHP*

這就是弱點對營運成本的影響：每出一個漏洞，就要有人追公告、判斷影響、升級、測試、上線，而且時間點由漏洞決定。10 月 23 日，剛好是颱風假第一天，PHP 又公告了一則相關的資安通知（CVE-2026-115560），在特定設定下，連已經修補的版本也受影響，要等下一版才會修。

小屋跑在 Cloudflare Workers 上，沒有用 PHP，執行環境的修補交給 Cloudflare。自己用到的套件開了 Dependabot，有漏洞會自動開 PR，Grok Bot 巡檢時也會一起看。

對用戶來說，他沒辦法幫你修，只能相信你會修。營運方沒修，資料外洩、服務中斷、換密碼換 key，最後都是用戶在承擔。

### 像洋蔥一樣拖時間

防守像洋蔥，一層一層的，目的是拖延時間，讓你有時間應變。所以還是要有人巡邏、有人應變，這些都是成本；現在透過 AI，這些成本可以降下來。

小屋上線到現在沒遇過真的攻擊，常見的爬蟲倒是一直有。這些在 Cloudflare 的防火牆規則上已經擋掉；repo 裡本來也不放 .env 或 .php，爬蟲來掃基本上都是 404。

## 企業客戶會問的四件事

如果我做的是 SaaS，企業客戶常問四件事：資料有沒有加密、登入有沒有 MFA、出事查不查得到紀錄、多快能應變。我拿小屋一項一項對：

- **加密**：token 已經在應用層加密，是最近有人開始試用時補上的。角色圖、頭像這類圖片沒有加密；對話與任務內容接下來會逐步加密。
- **MFA**：用戶走 Clerk 的社群登入（Google、LINE、X），目前沒有強制 MFA。Clerk 要付費方案才能在正式環境開 MFA，暫時沒有打算，大家要顧好自己的社群帳號。Cloudflare 管理介面是帳號密碼加硬體金鑰 MFA；Cloudflare One 可以再多一層，小屋目前沒有後台，暫時還沒用。
- **紀錄**：查用戶業務資料會留 audit 紀錄，之後可以追查；是不是 bot 做的，目前還分不出來，之後補強。
- **應變**：最重要的是 key rotation。換新 key 部署後，舊資料用舊 key 解密、新 key 重新加密，這部分正在做。難的是發現得夠早：攻擊者把 key、程式碼和資料一起打包下載，就能自己解密。換成 AI 來做，這段時間會變得非常短。

## 麻煩的事交給 agent

CI 部署、bot 查資料都要用到 API token，而這些 API 不一定經過 MFA。所以上集講過，每把 token 都設成最小權限，弄起來麻煩，但外洩一把 key 時，損失範圍有限。

最小權限、環境隔離、變更留紀錄，大企業和金融業本來就在做，只是流程很花時間，小團隊常常跳過。這些剛好是 agent 擅長的：重複、有規則、要細心、不能漏。像小屋有一份 1700 多條的 IP 清單，交給 agent 定期更新、比對、回報差異。

巡邏也一樣。我讓 Grok Bot 定期巡檢錯誤、各間小屋的 bot 數量和工具使用情況，看的是業務與管理數據，不必看用戶內容。有一次它發現一間小屋上傳頭像連續失敗四次，問我要不要派工；派工後查出後台有錯誤紀錄，前台卻沒有清楚提示。原因是頭像只收正方形，用戶自己傳了長方形。bot 從 MCP 收到指令時本來就知道要傳正方形，所以一直沒發現。

以前的選擇是二選一，新創選快，金融業選嚴謹。現在很多麻煩的合規和防護工作可以交給 agent，「太麻煩所以不做」的理由就站不住了。

## 小屋的做法與取捨

小屋目前只加密了 token。金鑰在我手上，我解得開，但不會去解：這些 token 不是我需要的東西，也關乎服務的信任。加密的用處在於拖時間，假設我的 Cloudflare 帳號外洩，對方查到的是密文，還得知道程式怎麼寫才能解開，我就有時間發現異常登入並應變。

資料收到什麼程度？小屋會收錯誤率、關鍵使用數據，以及有多少間小屋完成新手教學，用來判斷大家是否適應、流程要不要改善。

![小屋統計腳本輸出：新手教學漏斗](/blog/ep085/zh-TW-07.webp)
*小屋統計腳本輸出：新手教學漏斗*

小屋裡的對談內容不是我要處理的東西，所以要加密：AI 無人值守維護時，走正常管道看不到內容；bot 因為 prompt injection 或自己出錯想把內容撈出去時，也多一道擋。代價是 Cloudflare 內建的搜尋用不了，例如咖啡師要搜自己的聊天紀錄，就得在應用層自己做。端到端加密更安全，但新住戶加入、搬移、離開時的機制都會變複雜，這也是取捨。

## AI 新漏洞：prompt injection

prompt injection 是把指令藏在 bot 會讀的內容裡，像網頁、信件、GitHub issue，bot 讀到以後就被帶著走。小屋自己取內容走固定規則，但 bot 需要額外資訊時會不會自己去外面抓，小屋管不到，這部分需要我們共同承擔。

萬一真的有一隻 bot 被控制，以小屋現在的權限設計，它只查得到自己屋子的東西：一間屋子一個 Durable Object，資料本來就分開。Cloudflare 也有擋 prompt injection 的 AI Security for Apps，偵測欄位要 Enterprise 付費加購。

## AI 做事，人判斷

AI 很會做事，但它不會替你判斷什麼不該做。小屋一開始只是 side project，我偷懶給了 Grok Bot 一把全範圍的 token。角色定義裡寫了哪隻管 staging、哪隻管 production，但那只是 prompt 的約束，它還是可能查錯環境，所以後來我把權限切開。

AI 給的常常是平均答案，資安偏偏在不平均的地方出事。我不懂的時候，連「這把 token 權限開多大」都問不出來，AI 也不會主動提。citizen developer 最大的風險，是不知道自己不知道什麼。

## 商業取捨

新創初期活下去是第一要務，資安通常一步步調整。缺少資安意識會走向兩個極端：一開始什麼都不敢做而落後，或者做大以後沒有跟著加強。我認為營收應該提撥一部分做資安，跟被勒索的風險對沖；一個月賺一百億，被勒索一成就是十億。

## 上線前的三個問題

下次把專案交給 AI、或丟上一鍵部署平台之前，先問自己：

1. 我的鑰匙放在哪？API key、資料庫密碼是誰在保管？
2. 權限開多大？這把 key 被偷了，最壞會怎樣？
3. 出事了，誰會發現？是我自己先發現，還是等新聞告訴我？

部署已經不是瓶頸，AI 讓一個人做出以前一個團隊的量，但量越大，資安的洞也越大。複雜度不再是擋人的理由，資安不能省。
