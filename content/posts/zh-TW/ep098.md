## 老闆要 AI 策略，同事要能用

現在公司的老闆，大概都會說：要用 AI 提升生產力。可是具體怎麼做，通常很迷。

公司要每個部門都提出自己的 AI 策略。我頂頭老闆出的題目是：怎麼把資深工程師的經驗留下來，讓新人更快上手，提升每個人的產值。

部門裡有很多人不寫程式。前陣子我們辦了一場 vibe coding 黑客松，用的是 Codex；可是行銷、業務同事要駕馭 coding agent，還是很難。

剛好 Grok Bot 最近很紅：給你一群 AI 員工，交代一句就去做事，不用碰程式。可是它這陣子又降智又縮水，帳號綁在個人身上，公司的信跟資料要送到外面，公司也不太可能為了這個幫每個人付一份訂閱。

所以這兩週，我架了一套開源的 Grok Bot 平替：[Rakazo](https://github.com/elie222/rakazo)。先在筆電上試，後來搬到公司的主機，目前只開給我們部門試用。它是 Apache 2.0 授權，我錄影片那天 GitHub 上有七千九百顆星，可以接公司自己的模型。翻它的文件，越看越覺得它從一開始就有想到企業。

[主管才懂那一集](/blog/ep082)我說過，自己架開源的 agent 要天天顧。這次真的架了，就把實際碰到的事攤開來講。

## Grok Bot 有的，它大多都有

拿 Grok Bot 來對照，Rakazo 大多都有：

- 每隻 bot 有自己的電腦畫面，有瀏覽器、有終端機。
- 可以排程，每天固定時間做事。
- 可以開群組，@ 一下，幾隻 bot 分工。
- 要動手改東西之前，先問你一聲。

![把整間辦公室搬回自己公司](/blog/ep098/office-move.jpg)

多出來的是三件事：

1. **模型自己選**：接你自己的金鑰，或者公司自己架的模型。
2. **bot 的電腦放哪裡自己選**：本機的 Docker，或租雲端的沙盒。
3. **整套裝在你自己的機器上**。

講白了，就是把 Grok Bot 的整間辦公室搬回自己公司。

排程之外，伺服器有開收信的話，bot 也能被一封信或一個 webhook 叫起來，每一次執行都留紀錄。它也會自己做儀表板跟文件，產生分享連結。要注意，拿到連結的人不用登入就看得到，公司的資料別亂分享。

搬家它也想好了。原本在 OpenClaw 或 Hermes 養的 agent，選資料夾就能匯進來，指令、記憶、技能一起帶。用 ChatGPT 或 Claude 的，它給你一段提示詞，叫舊的 AI 把自己的設定寫下來，貼回來就是一隻新的 bot。

## 開成連鎖店，總部在意的四件事

為什麼說它有想到企業？想像你開一間咖啡店，後來開成連鎖。一家店自己顧，老闆什麼都看得到；開到十家店，在意的就變成四件事：

![咖啡店開成連鎖，總部在意的四件事](/blog/ep098/chain-hq.jpg)

1. 分店之間不能亂拿東西。
2. 店員動收銀機之前要先問。
3. 會動到東西的事要記帳。
4. 只有自己的員工進得了門。

Rakazo 的文件，剛好一件一件對上。

### 分店各有廚房：Space

工作區在 Rakazo 叫 Space。每個工作區有自己的 bot、對話、記憶、電腦，還有連好的 app。bot 預設只能跟同一個工作區的 bot 講話，業務部的資料，研發部的 bot 碰不到。

![Rakazo 文件：Space 裡的東西預設不跨工作區](/blog/ep098/spaces.jpg)

### 動收銀機先問：Approvals

Grok Bot 也會先問，Rakazo 把批准分成三種模式：

| 模式 | 做法 |
| --- | --- |
| Ask | 只要會改到東西，像寄信、改文件，就先問你。 |
| Auto | 另外派一個模型來審，動作跟你交代的事對得上就放行，偏題或收不回來的才問你。 |
| Never ask | 全部直接做。 |

問你的時候，對話裡會跳出一張卡片，寫清楚它要做什麼。你可以只准這一次、以後都准，或直接拒絕。卡片不會卡住對話，你可以繼續跟 bot 聊，有空再回。

### 總部的帳本：Audit log

會動到東西的動作是哪隻 bot 或哪個人做的、誰批准的、哪個設定跟憑證被改過，都記下來，而且一直開著。訊息內容、工具參數跟密碼，它刻意不記。要交給資安團隊，可以匯出，也可以直接轉進公司的監控系統（SIEM）。

![Rakazo 文件：Audit log 記錄的動作](/blog/ep098/audit.jpg)

### 員工卡才進得了門：SSO 與白名單

- 接公司的單一登入（SSO），用公司帳號登入。
- 設白名單，只有公司信箱能註冊。
- 有接 SCIM 目錄同步的話，同事離職，公司帳號一停用，這邊也跟著關。
- 資料庫做了列層級隔離，每一筆資料在資料庫這一層就分好是誰的。

批准這件事，一個人用也用得到。可是稽核紀錄交給資安、目錄同步停帳號、只准公司信箱註冊、資料庫分層隔離，這些都是一整間公司一起用才需要的東西。它把這些寫進文件，代表一開始就有想到企業。

## OpenMausBot 還是 Rakazo？

十月底選型的時候，我要找一個像 Grok Bot 的 personal agent，條件是：

- 同事不用安裝，網頁跟手機打開就能用。
- 會排程、主動做事。
- 寫入之前先問。
- 能接公司登入。
- 能接公司自己的模型。

OpenClaw、Hermes 我也看了，它們比較像一個人用的 agent，要給一群人用，還得自己再包一層。最後剩下兩個 Grok Bot 型的候選：[OpenMausBot](https://github.com/milind-soni/OpenMausBot) 跟 Rakazo。

選 Rakazo，主要看多人協作跟企業這一塊。OpenMausBot 預設用你電腦上登入的 Claude、Codex 這些 CLI，走個人訂閱。我要的是接公司 GPU 上的模型、用公司帳號登入、一個站台給整個部門用。權限控制、電腦分團隊跟私人，這些設計 Rakazo 的文件跟預設都寫得比較完整，放到公司裡正好用得到。換成一個人自己用，答案可能就不一樣。

順便講一個觀念。用 AI 寫程式之後，我也常想：乾脆自己寫一個。agent 我寫得出來，可是多人登入、權限、稽核、手機 app，這些人家已經做好了，自己從頭寫會多花很多時間。所以我把力氣放在現成的沒做到的地方：接本土郵件系統的 CLI、個資遮罩、用量頁。你用 vibe coding 動手之前，也可以先問一句：有沒有現成的？

## 從筆電搬到公司主機

### 第一個情境：日常雜事

收信、回信、查聯絡人、看行事曆、訂會議室，各家都有接，Grok Bot 也接了 Gmail。可是台灣公司常用一些比較少見的本土系統，我們的郵件系統就是，現成的接法接不上。

所以我自己寫了一個命令列工具（CLI），接那幾個老牌的通訊協定：IMAP 收信、SMTP 寄信、CalDAV 管行事曆、CardDAV 管通訊錄。bot 要看信、查人、訂會議室，就叫這個工具。

為什麼用 CLI，不用 MCP？MCP 是現在 AI 接工具的標準做法，可是遠端的 MCP 通常走 OAuth 登入。多人一起用的時候，要把這些老協定的登入方式轉成 OAuth 那一套，實在太繞了。另外，它們查起來很慢，先把信同步到本地、再從本地查，bot 才不用每次都等半天。算下來，CLI 最簡單。

### 模型：公司自己的 GPU

能跑的最大是 Gemma 4 的 31B，不過它回應比較慢，日常用的是小一號的 E4B。上一代的 Gemma 3，選型時就先排除了。Google 公布的代理評測（τ2-bench Retail），開思考模式的 31B 有 86.4%，E4B 是 57.5%，Gemma 3 只有 6.6%。

![Gemma 4 的代理評測分數](/blog/ep098/gemma4-bench.jpg)

小模型能力還是差一截。所以我做了一套評估：選一批日常任務，拿 OpenAI 的 GPT-6.1 Sol 跟 GPT-6 Luna 當基準，看小模型完成到什麼程度；再拿大模型做出來的結果，回頭去改技能跟提示詞，讓小一點的模型也比較照著規矩做。

### 筆電會睡覺

![每天早上 9 點的排程，碰上剛睡醒的筆電](/blog/ep098/sleeping-laptop.jpg)

一開始我架在自己的筆電上，設了一個排程：每天早上 9 點幫我看信、整理摘要。結果第一次執行，連續三天都失敗。查下去才知道，9 點的時候 Mac 剛從睡眠醒來，網路還沒起來，連模型的網址都查不到。Rakazo 大概 12 分鐘後會自動重試，三天都有補成功，只是摘要每天晚了 20 到 40 分鐘。

AI 員工要準時上班，就得住在不會睡覺的機器上。所以我申請了公司的一台主機，把它搬上去，目前只開給部門裡試用的同事。

### 兩道門

搬上去這幾天，我陸續加了兩道門：

1. **登入**：走公司帳號，而且只放行特定的部門群組。
2. **模型呼叫**：不管用哪個模型，呼叫都得先經過一個閘道。

給不寫程式的同事用，最重要的是打開就能用。所以每個人登入之後，第一隻 bot 就是預先設好的日常秘書，開場先問你是業務、行銷還是技術，照角色給一套現成的用法。模型清單也在登入時自動同步，不用每個人自己填模型網址。

### 閘道：護欄、遮罩、用量

模型呼叫的閘道，用的是開源的 [new-api](https://github.com/QuantumNous/new-api)。有些任務公司自己的模型還是吃力，所以我也開放同事接外部的模型，可是一定要走這個閘道。閘道卡在中間，我就能自己插一段程式：

- 送出去之前先過一層護欄。
- 把個資遮掉。
- 每一次呼叫用了多少，都記下來。

我拿這份紀錄做了一個用量頁：每個人登入就看得到自己這陣子用了多少，還有一個排行榜。誰真的在用，一看就知道。

## 三條規矩、五隻 bot、一步一步放手

### 三條規矩

1. **資料來源只認團隊原本的工作系統**。bot 負責讀、整理、起草；要寫回去，只走三條路：在原本的工作項目底下留言、提修改建議，或開一頁放進待審區，人看過才生效。
2. **個人的事放個人工作區，團隊的事放團隊工作區**。團隊的 bot 一律不碰個人的信箱。
3. **先選已經有流程、只是很花時間的工作**，不另外發明新流程。

### 五隻 bot

先講清楚：現在上線的只有個人助理，其他四隻都還在規劃。

| bot | 做什麼 |
| --- | --- |
| 週會助理 | 每週一早上讀團隊的工作項目，整理已過期、本週到期、很久沒更新三份清單，照人寫好週會報告草稿，貼到團隊群組。 |
| 知識庫助理 | 同事問問題，它從流程文件、廠商資料跟技術筆記找答案，附上來源頁面。工作項目做完時，把能重複用的內容整理成技術筆記草稿放進待審區。大家跟它的對話，它也會濃縮成筆記；不想被收進去的人可以選擇退出。 |
| 售前助理 | 輸入客戶的痛點，參考過去的方案，起草建議書、POC 計畫跟報價框架。範本穩定了就做成技能，全部門都能叫。 |
| 異常追蹤 | 每週掃一次專案總覽，抓出卡住太久的專案，提醒負責的人。 |
| 個人助理 | 負責信件摘要，前面講的日常秘書就是它的第一版。 |

老闆那一題，我打算靠知識庫助理來回答：資深同事的經驗留得下來，新人有問題先問它。

### 順序

1. **前兩週**：只用我自己跟一兩個測試帳號，把信件摘要跟週會助理跑順，只讀、不寫回。
2. **第三、四週**：做完隔離測試、接上團隊共用的連線，再找一兩位同事試用。
3. **都穩了**：才開給整個部門。

![AI 員工跟新人一樣，先給只讀](/blog/ep098/new-hire.jpg)

這段是我覺得最主管才懂的地方。AI 員工跟新人一樣：先給只讀的權限，做出成績、大家信任了，才慢慢放手讓它寫。用量頁看得到誰在用；每隻 bot 每週幫大家做掉多少工作，我打算另外算，一起拿到週會上講。

## 架下去才知道的四個坑

### 1. 預設的電腦是大家共用的

同一個工作區的 bot，預設共用一台團隊電腦。每隻 bot 雖然有自己的資料夾，那只是分類，擋不住別人：你的 bot 登入過的網站、下載過的檔案，同一台電腦上的 bot 都碰得到。公司要用，就要改成私人電腦，讓每個人只有一台。

### 2. 內網只能全開或全關

安全模式下，bot 的電腦連不到公司內網，信箱、內部系統都碰不到；切成開放模式，又變成整個內網都摸得到。要只開信箱這一條，就得自己寫防火牆規則。公司網路這邊也要先申請開通，網域、防火牆，每一樣都要走流程。

### 3. 資源

每台 bot 電腦預設 2GB 記憶體、2 顆 CPU。照預設算，一台主機的記憶體開個幾十台大概就滿了。一個部門全部開起來之前要先算這筆帳；人多的時候，有些工具要改成放在伺服器統一跑，每台電腦就不用各跑一份。

### 4. 維護

上游改得很兇，我一次升級就追了 407 個 commit；搬上公司主機之後五天，合併請求就開到第 16 個：升級、修漏洞、改部署流程。所以我分了測試站跟正式站：合併進主線，先自動部署到測試站；正式站只從版號上線，壞了就把舊的版號再跑一次退回去。上游的映像檔，每週一固定掃一次漏洞。這套做法，[上一篇的 CI/CD](/blog/ep097) 拆開講過。

## Grok Bot 還是 Rakazo？

**一個人用**，想要打開就有、不想顧主機，Grok Bot 還是最省事。額度縮水，就是你為了省事付的代價。

**開給一整個團隊**，公司的資料要管得住去向、要留稽核紀錄，而且有一個人願意花時間顧它，Rakazo 很值得試。換到的是模型自己選、送出去的內容先遮掉個資、會動到東西的動作都查得到。

主管才懂那集我說過：agent 可以換，管它的那一層要留著。我的做法是派工、驗收、交接、額度這些事放在 agent 外面管；裡面那隻換成 Rakazo，管法原則上一樣。

## 導入前檢查清單

我目前的答案，是先讓 AI 員工住進部門：呼叫都經過公司自己的閘道、個資先遮掉、會動到東西的事都有紀錄。代價是得有人顧。

你也想試的話，先架一套只開給自己，拿一隻個人助理跑兩週，只讀不寫，跑順了再找一兩位同事一起用。開給更多人之前，拿下面這份清單跟你們的 IT 對一次。

### 模型

- [ ] 用哪個模型？公司自己架的，還是外部的？外部模型的呼叫有沒有統一經過一個閘道？
- [ ] 送出去之前，個資有沒有遮掉？每次呼叫有沒有留用量紀錄？
- [ ] 小模型做不好的任務，有沒有一套評估，拿大模型的結果回頭改技能跟提示詞？

### 登入與權限

- [ ] 用公司帳號登入（SSO）嗎？只放行特定群組？
- [ ] 註冊有沒有白名單？同事離職，帳號會不會跟著關（SCIM）？
- [ ] 批准模式選哪一種？會改到東西的動作，是不是都要人批准？

### 稽核

- [ ] 稽核紀錄有沒有開？要不要轉進公司的監控系統？保存多久？
- [ ] 分享連結免登入可看，有沒有跟同事講清楚哪些東西不能分享？

### 電腦與網路

- [ ] bot 的電腦改成私人的了嗎？還是整個工作區共用一台？
- [ ] bot 要連公司內網的哪幾個服務？防火牆只開那幾條了嗎？
- [ ] 網域、防火牆這些開通，申請流程要多久？
- [ ] 每台 bot 電腦要多少記憶體跟 CPU？一台主機開得了幾台？

### 維護

- [ ] 誰負責追上游、修漏洞？
- [ ] 有沒有測試站？正式站能不能一個動作退回上一版？
- [ ] 上游的映像檔有沒有定期掃漏洞？

### 導入節奏

- [ ] 前兩週只讀、不寫回？
- [ ] 隔離測試做完，才找同事試用？
- [ ] 怎麼算效益：誰在用、每隻 bot 每週做掉多少工作？
