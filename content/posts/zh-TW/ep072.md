## 帶團隊 Mindset：從盯終端到驗收成果

以前用 Codex，掌控感都來自畫面：它打開哪個檔案、改了哪一行、跑了哪個指令我都看得到，不對就隨時中斷。這很爽，但代價是你整個人被綁在視窗前面——它在做事，你在看它做事，等於兩個人力只做出一份產出。

換成個人助理（像 Grok Bot 或 Dots），工作都在背景跑，做完才回來報告。你看不到過程，第一個反應就是失控感。

但你想想平常怎麼帶工程師：你不可能整天坐在他背後盯著螢幕看他打每一行 code，那叫監工。你會交代清楚要什麼、何時交、怎麼驗收，然後挑關鍵點抽查。

**掌控沒有消失，只是從「看得到過程」搬到「做完是什麼樣子」。** 定義好驗收訊號，把親手掌控的焦慮轉成放心的驗收標準。

## 拆成員與職責：各司其職避免 context 混亂

不要試圖用同一個 bot 包辦所有事情。建議至少拆成：

1. **個人總管（Lead Bot）**：負責接收日常口語指令、評估任務難度、派工給專業成員，並把成果收回來向你回報。
2. **專業成員（Specialist Bots）**：例如「頻道小編」專門改稿、抓事實查核；「工程助理」專注寫程式與跑測試。

每個成員擁有各自乾淨的 context 與工具設定，不會互相干擾。

## 接工具與辨識：Grok Bot Integration

在串接工具（如 Notion）時，很多人會直接用 OAuth 授權，但這樣所有操作都會以「你本人」的名義送出，很難分清哪些是 AI 改的、哪些是你寫的。

更好的做法是到 Notion 建立專屬的 Integration（例如建立一個名為 Grok Bot 的內部整合），給予適當的頁面權限。這樣每一筆修改、每一則留言都會清楚標記是 Grok Bot 處理的，責任邊界清楚，也不怕個人憑證權限過大。

## Webhook 門鈴與 Cloudflare Workers 轉接

要讓 Notion 留言能即時叫醒 Grok Bot，核心就是建一條 Webhook 門鈴。但 Notion 與 Grok Bot 兩邊的驗證機制天生不同：

- **Notion 門鈴驗證**：Notion 關心的是「這個網址是不是你的」。第一次設定時會發送 `verification_token` 到你的 endpoint，你要把 token 貼回 Notion 完成所有權驗證；後續每次請求則會帶上 `X-Notion-Signature` 簽章。
- **Grok Bot 櫃台驗證**：Grok Bot 關心的是「你是誰」。它的 Routine Webhook 要求每次請求都必須附帶 `Authorization: Bearer <secret>`。
- **Notion 的痛點**：Notion 官方的 Webhook 設定頁面裡，根本沒有地方讓你填自訂的 Header（例如 Authorization Header）。

所以我們需要 **Cloudflare Workers** 當作中間的轉接橋樑：

1. **對外（Notion）**：處理所有權驗證，接收 Notion 送來的事件。
2. **對內（Grok Bot）**：補上 Bearer Token 身份認證，轉發給 Grok Bot Routine。
3. Worker 本身不存資料，只轉一手，安全又快速。

相關開源與參考文件：

- [Cloudflare Workers 官方文件](https://developers.cloudflare.com/workers/)
- [Notion Webhooks 官方文件](https://developers.notion.com/reference/webhooks)
- [notion-webhook-relay 公開檢查端點](https://notion-webhook-relay.dnplus.workers.dev)

### 現況規則與防迴圈

在 Grok Bot 的 Routine 裡設定：

- 只訂閱 `comment.created` 與 `comment.updated` 事件。
- 排除 Grok Bot 自己的 integration ID，避免自己回覆觸發自己造成無限迴圈。
- 別人留言時僅通知並可擬草稿，不自動送出；只有你本人在討論串明確叫它回時，它才會直接回覆。

## 多電腦操作：Grok Bot vs Dots 的巨大差異

這也是 Grok Bot 與 Dots 在實用性上最大的分野：

- **Grok Bot**：支援連線多台電腦（例如家裡 Mac 與公司工作機）。你可以設定一律允許操作或每次詢問。只要目標電腦當前處於 active 狀態，Grok Bot 就能靈活切換操作；如果電腦閒置過久，系統會自動斷開連線，兼顧便利與安全性。多數工作只要模糊交代一句，它自己知道在雲端電腦自主跑完（抓 code、改寫、跑測試到開 PR）。
- **Dots**：一次只能綁定單一電腦。如果你昨天在家用家用電腦，今天到公司用公司電腦呼叫它，Dots 依然連在家裡電腦，完全無法操作當前的環境，必須手動進設定明確切換，體驗非常卡頓。

## 寫 Code 兩條路：內建 Cursor vs 外部手

1. **Cursor 雲端 Agent**：適合標準、封閉、不碰本機環境、改完直接發 PR 的任務。
2. **herdr / 外部 Coding Agent**：需要本機終端、真實硬體、私有環境，或想使用閒置 coding agent 額度時，透過外部手掛載，由總管負責發號施令。做完一樣可以打 webhook 敲門回報，不用人肉輪詢。
