## 續集對帳（2026-09-10）

巴尼爾開續集：軟體多半有替代，主力仍不敢搬（M5／生態＋Setapp／公司機）。主推「Omarchy 上該有的我都有——為何主力還是 Mac？」。對帳頁：題材提案｜Omarchy 續集

我當初是從 Windows 換到 Mac 的。用久了，確實有點被 Apple 生態綁住。但老實說，macOS 我是越來越不滿意。要不是 Apple Silicon，也就是蘋果自己設計的晶片系列，真的強，我還滿想脫離的。

最近用 Omarchy，倒是讓我開始覺得：欸，好像真的有機會再換一次。

## Omarchy 是什麼？

Linux 可以先理解成 Windows、macOS 之外的另一種作業系統選擇。它有許多把系統、工具和設定打包好的版本，通常叫「發行版」。Omarchy 以其中的 Arch Linux 為基礎，把桌面、熱鍵、開發工具和 AI 工具整理成一套可以直接開始用的環境。

它使用的 Hyprland，負責視窗怎麼排列、怎麼切換，強調鍵盤操作，也能自動排列視窗。這些選擇放在一起，才是我實際每天碰到的桌面體驗。

## DHH 是誰？

DHH 是 David Heinemeier Hansson 的名字縮寫。他是 Ruby on Rails 的創作者；Rails 是幫工程師開發網站的工具框架。他也是 37signals 的共同擁有人，那家公司做的 Basecamp，是讓團隊整理專案、溝通和工作進度的軟體。

這次他把自己想用的 Linux 工作環境做成 Omarchy，讓其他人也能裝來用。不認識 DHH 也沒關係，對我來說，最後還是要看這套環境能不能拿來做事。

[DHH 本人介紹](https://dhh.dk/)

這也是它吸引我的地方。Linux 能做什麼，我大概知道；但一套每天願意打開來用的桌面，整合得好不好，差很多。

[Omarchy 官網](https://omarchy.org/)

## 我真的在用哪些機器

我有一台老 MacBook Pro，裝了 Omarchy 當開發機；另外一台 ZimaBoard 小型電腦，8GB 記憶體，也有裝。Mac 上的 Try Omarchy 我也有用：它在 macOS 裡開一台虛擬電腦來跑 Omarchy，原本的 Mac 環境還在，可以先熟悉桌面和工具。整體用下來，流暢度不錯。

不過我的主力目前仍然是 MacBook Air M5，24GB 記憶體。現在是不同機器分工，還沒有全面搬家。這裡講的流暢度是自己的使用感受，沒有拿同一台機器做效能跑分比較。

## 沒中文輸入法？我就打了一句英文

第一次安裝完，它先讓我設定 agent。Agent 就是能幫你動手執行工作的 AI 助手：工具和權限接好後，它可以查檔案、跑指令、改設定，不只是在聊天視窗給建議。

設定好了，然後勒……沒有中文輸入法。AI 先準備好了，我還不能打中文。那好吧，現成的幫手就在這裡，先叫它處理看看。

我就開 Codex，打了一句：

> i need chinese ime

Codex 是我用的 AI 開發助手；IME 是輸入法的英文縮寫。整句就是「我需要中文輸入法」。然後它就自己搞定了。

這件事讓我對 AI native 很有感。缺一個功能，我可以直接跟 agent 說我要什麼，讓它幫我處理系統設定。對我來說，這比一句「內建 AI」的宣傳有感多了。

## Container、桌面與熱鍵，才是每天的理由

我本來就常在 Mac 用終端機，也就是打文字指令來操作檔案、啟動程式的視窗。Linux 也常用這種操作方式，所以很多觀念和習慣接得上。這是我的上手背景；第一次接觸的人，適應時間可能會不同。

Container 可以先理解成把程式需要的執行環境收在一起，跟其他程式分開管理。比如專案需要資料庫，就能替它啟動一套環境，減少套件彼此干擾。很多開發環境用的是 Linux container：在 Mac 上通常需要一層 Linux 虛擬機，在 Linux 上則可以直接運行。對我來說，開發更方便。

Omarchy 又把桌面一起整理好，開發和日常操作都顧到了。熱鍵就是按一組鍵盤按鍵，直接完成操作；切換視窗、開工具這些事情，常用操作可以留在鍵盤上。每天用很多次，順不順手，感覺很直接。

[Docker：Mac 上的 Linux 虛擬機](https://docs.docker.com/desktop/features/vmm/)

AI 相關外掛要接 email、calendar 這類辦公用途，也有方便的地方。這部分是我的使用體感，具體能做到什麼，還是看自己選的工具與服務。

Hermes 也是一套 AI agent，官方最近也在推進它與桌面的整合。官方手冊裡能看到預設 agent、桌面與主題整合等內容；不同安裝版本不一定同時具備所有功能。

[官方 AI 手冊](https://github.com/omacom/omarchy/blob/quattro/manual/17-ai.md)

## 少女前線 2 崩潰了，我就叫 agent 查

Linux 打遊戲，現在也值得重新看。Omarchy 提供 Steam 安裝入口，相容的遊戲可以在 Steam 裡下載、安裝、按下遊玩，操作流程已經很接近平常用 PC 的習慣。

Steam 是買遊戲、安裝和啟動遊戲的平台，也有 Linux 版。Proton 是它整合的相容工具，幫忙把 Windows 遊戲的要求轉成 Linux 能處理的方式，本身用了 Wine 的技術。Wine 和 CrossOver 都是協助 Windows 程式在其他系統運作的相容工具；透過 Steam，很多相容的遊戲不需要自己先把這套環境全部配置一遍。

我自己有跑《少女前線 2》，一開始就崩潰了。我馬上叫 agent 查，印象中好像是 DX11 有什麼問題，改完就可以玩了。雖然有點慢啦。

DX11 是 DirectX 11 的簡稱，是 Windows 遊戲常用來跟顯示卡等硬體溝通的一套介面。我只記得印象中和它有關，確切改了哪個設定，現在記不清楚。能玩跟玩得順也有差，遊戲相容性仍然要逐款看，反作弊、啟動器和驅動都可能影響結果。

但這個過程我覺得很方便：前面缺中文輸入法，可以找 agent；現在遊戲出了問題，也能叫它幫忙查、幫忙改。

[Omarchy 遊戲手冊](https://github.com/omacom/omarchy/blob/quattro/manual/26-gaming.md) · [Valve Proton](https://github.com/ValveSoftware/Proton)

## 社群有風波，我還是覺得值得一試

Omarchy 在 Linux 社群確實有爭議。有些人不認同 DHH 的政治言論；例如 Framework 提供開發硬體、宣傳 Omarchy，就曾在它的社群引起反彈。Framework 創辦人回應，他們以推廣開源軟體作為合作考量，並澄清提供的研發機器與金錢贊助不同。這是圍繞人物與合作選擇的爭議，不能直接拿來代替產品的技術判斷。[Framework 當事人回應](https://community.frame.work/t/framework-supporting-far-right-racists/75986/2) · [研發硬體說明](https://community.frame.work/t/framework-supporting-far-right-racists/75986/1611)

技術方面，也有人質疑它的預設配置和更新方式，認為使用者應該更容易選擇哪些設定要跟著更新。[專案內的配置討論](https://github.com/omacom/omarchy/discussions/2896)

安全問題則有具體紀錄。官方在 2026 年 8 月 25 日的 4.0.1 更新中，列出了影片下載、通知點擊動作等安全修正，也調整了 AI agent 的預設審查方式。這些批評值得認真看；修正特定漏洞，也不代表整套系統從此沒有其他風險。[4.0.1 官方修正紀錄](https://github.com/omacom/omarchy/releases/tag/v4.0.1)

不過我自己用下來，還是認為 Omarchy 非常值得一試。問題該修就修，開發、桌面、熱鍵和 agent 帶來的方便，我也確實用到了。主力還沒搬家，但我會繼續用，看看它能走到哪裡。

## 還沒搬家，但開始看見可能

目前最煩的還是 ARM 支援不夠完整。ARM 是一種處理器指令架構，Apple Silicon，也就是蘋果自己設計的晶片系列，使用的就是這類架構。它跟許多 Intel、AMD 電腦使用的架構不同，軟體和硬體驅動需要對應支援。Try Omarchy 讓我能在 Mac 上體驗，但虛擬機能跑，跟不同 ARM 硬體都能原生安裝、套件都完整支援，是不同的事。不能因此推論 M5 已經有完整裸機支援。

Apple Silicon 的吸引力還在，生態也確實把我留住了一部分，所以主力仍然是 M5 Air。不過 container、桌面、熱鍵和 agent 的整合，已經讓我覺得往 Linux 走是有機會的。

Omacom Foundation 是協助 Omarchy 及其依賴的開源專案持續發展的基金會。看到它的投入，還有工具整合持續往前走，我滿期待。當初從 Windows 換到 Mac，現在又開始考慮下一次了。希望 Omarchy 越來越好。

你也有想過離開 macOS，或正在用 Linux 當主力嗎？歡迎聊聊你的經驗。
